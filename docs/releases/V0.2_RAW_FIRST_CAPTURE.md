# v0.2 – Raw-first Capture-Modell

## Zweck

v0.2 führt die erste zukunftsfähige Core-Grenze des Forks ein. Eingehende
ChatGPT-Antworten werden als unverändertes Rohmaterial gesichert und erst
danach für abgeleitete Darstellungen normalisiert. Dadurch können spätere
Parser- oder Exportänderungen das ursprüngliche Ausgangsmaterial nicht
unbemerkt verändern.

## Architekturentscheidung

Der Core kennt weder Chrome, DOM, Tampermonkey noch Netzwerkzugriff. Er arbeitet
mit Text, strukturierten JSON-Daten und expliziten Funktionen:

```text
Response-Text
    │
    ▼
captureResponse
    │
    ├── raw.text       exakt empfangener Text
    ├── raw.value      geparste Sicht
    └── source         Herkunft und optionale Chat-ID/URL
             │
             ▼
       withNormalization
             │
             └── normalized  optionale, abgeleitete Sicht
```

`raw.text` ist die maßgebliche Rohrepräsentation für einen späteren
Raw-Download. `normalized` ist jederzeit verwerfbar und wird nicht als Ersatz
für das Original behandelt.

## Umgesetzte Bausteine

| Baustein | Umsetzung |
| --- | --- |
| Versionierter Datensatz | `CaptureRecord` mit `schemaVersion` |
| Herkunft | `CaptureSource` mit `kind`, optionaler Conversation-ID und URL |
| Exakte Antwort | `RawCapture.text` |
| Strukturierte Verarbeitung | `RawCapture.value` |
| Sichere Ableitung | `withNormalization` mit Deep Clone |
| Raw-Ausgabe | `rawText(record)` |
| Fehlerverhalten | Parsingfehler werden an den Aufrufer weitergegeben |
| Browserunabhängige Tests | Node-Testlauf ohne Chrome, DOM oder Tampermonkey |

## Qualitätsnachweis

Vor dem Abschluss wurden erfolgreich ausgeführt:

```text
pnpm lint
pnpm test
pnpm test:core
pnpm build
```

Die Core-Suite deckt drei Gates ab:

1. Der Antworttext und die geparste Struktur bleiben getrennt erhalten.
2. Eine mutierende Normalisierung verändert die Rohdaten nicht.
3. Ungültiges JSON wird als Fehler sichtbar und nicht als scheinbar gültiger
   Capture akzeptiert.

## Bewusste Grenzen

v0.2 ruft noch keine ChatGPT-API auf und lädt noch keine Datei herunter. Die
Anbindung einer Quelle erfolgt in v0.3 über die Extension-Shell. Der konkrete
Ein-Klick-Raw-Download ist das Ziel von v0.4.

Tampermonkey bleibt für diese Core-Schicht vollständig außen vor.
