# v0.7 – Batch-Robustheit und Fehlertransparenz

v0.7 verbessert die bestehende Batch-Queue für Mehrfach-Exporte. Ein erfolgreicher Batch bedeutet nun nicht mehr nur „die Queue ist beendet“, sondern wird anhand einer überprüfbaren Zusammenfassung bewertet.

## Was sich ändert

- Erfolgreiche Ergebnisse und fehlgeschlagene Requests werden getrennt geführt.
- Nach dem Ende eines Batches steht eine `QueueSummary` zur Verfügung:
  - `total`: Anzahl der eingeplanten Requests
  - `completed`: erfolgreich oder endgültig fehlgeschlagen verarbeitet
  - `succeeded`: tatsächlich erzeugte Ergebnisse
  - `failed`: Name, Versuchsanzahl und Fehlermeldung
  - `pending`: beim Abbruch noch nicht abgeschlossene Requests
  - `stopped`: Kennzeichnung eines manuellen oder systembedingten Abbruchs
- Die UI meldet partielle Batch-Läufe sichtbar, statt sie als vollständig erfolgreich darzustellen.
- Dauerhafte Fehler wie `Not Found` werden nicht sinnlos wiederholt.
- Netzwerk-, Timeout- und Serverfehler dürfen begrenzt mit exponentiellem Backoff wiederholt werden.
- Rate-Limits pausieren weiterhin die gesamte Queue und verwenden `Retry-After`, sofern vorhanden.
- Rohdaten erfolgreicher Captures werden durch Wiederholungen nicht verändert.

## Semantik der Ergebnisse

Ein Batch darf nur dann als vollständig erfolgreich gelten, wenn gilt:

```text
completed == total
failed.length == 0
pending.length == 0
```

Bei einem Abbruch oder endgültigen Fehler werden nur die nachweislich erfolgreichen Ergebnisse an den bestehenden Export-Callback weitergegeben. Die fehlenden Namen und Fehler bleiben in der Summary sichtbar.

## Architektur

Die Queue bleibt ein generischer Orchestrator. Sie kennt weder ChatGPT-Datenmodelle noch Dateiformate. Die Rate-Limit-Fehlerklasse liegt jetzt in `src/core/rate-limit.ts`, damit die Queue ohne Browser- oder API-Umgebung getestet werden kann.

## Tests

Die Core-Suite prüft:

- erfolgreiche und endgültig fehlgeschlagene Requests in einem gemeinsamen Batch
- exakte Versuchszahl bei begrenzten Retries
- keine Wiederholung permanenter Fehler
- Sichtbarkeit von In-Flight- und noch wartenden Requests nach Abbruch
- bestehende Raw-Capture- und Destination-Verträge

## Bewusste Grenze

v0.7 macht die vorhandene Mehrfach-Export-Queue zuverlässig. Es führt keinen neuen automatischen Hintergrundexport und kein anwendungsspezifisches Datenmodell ein. Jeder Batch bleibt eine explizit gestartete Nutzeraktion.
