# v0.6 – HTTP-Destination

v0.6 ergänzt neben dem lokalen Download eine explizit auslösbare HTTP-Destination.

## Nutzung

1. Im Extension-Popup eine `http://`- oder `https://`-URL eintragen.
2. **Endpoint speichern** klicken.
3. Optional **Endpoint testen** klicken. Der Test sendet einen `GET` ohne Capture-Daten; ein eigener Health- oder Status-Endpunkt ist dafür empfehlenswert.
4. Auf einer geöffneten ChatGPT-Unterhaltung **Aktuellen Chat senden** klicken.

Es gibt keinen automatischen Versand. Der rohe Chat wird erst nach dieser Aktion gelesen und als `POST` an den gespeicherten Endpoint gesendet.

## Payload-Vertrag

```json
{
  "schemaVersion": 1,
  "source": {
    "kind": "chatgpt-conversation",
    "conversationId": "…",
    "url": "https://chatgpt.com/c/…"
  },
  "raw": {
    "text": "{\"mapping\":{…}}",
    "value": { "mapping": { "…": "…" } }
  }
}
```

`raw.text` bleibt der unveränderte Antworttext. `raw.value` ist die geparste JSON-Struktur. `schemaVersion` ermöglicht spätere, kompatible Erweiterungen.

## Fehler- und Sicherheitsverhalten

- Nur `http` und `https` werden akzeptiert.
- Nicht-2xx-Antworten werden als Fehler angezeigt.
- Requests laufen nach 10 Sekunden (Endpoint-Test: 5 Sekunden) ab.
- Es werden keine Zugangsdaten gespeichert oder automatisch ergänzt.
- Die Erweiterung behält bewusst ihre engen ChatGPT-Host-Berechtigungen. Chrome kann Requests zu beliebigen externen Hosts ohne zusätzliche Host-Freigabe blockieren; für eine konkrete Integration muss diese Berechtigungsfrage bewusst und separat gelöst werden.

## Testabdeckung

Die Extension-Tests prüfen Envelope-Treue, JSON-POST, Statusfehler, URL-Schema, Timeout und den GET-Erreichbarkeitstest über injizierte Fetch-Implementierungen. Dadurch sind Payload und Fehlerfälle ohne echten Drittanbieter-Endpoint reproduzierbar.
